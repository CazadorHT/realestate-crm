# 📄 15: สถาปัตยกรรมเอกสารและสัญญาอัจฉริยะ (Smart Contracts & E-Sign Engine)

> **เทคโนโลยีหลัก:** Dynamic DOCX to PDF, Supabase Storage, RLS Security
> **เป้าหมาย:** สัญญาเอกสารต้องไม่ต้องพิมพ์ด้วยมือ และต้องห้ามถูกปลอมแปลงแก้ไข

ในระบบ B2B Enterprise การปิดดีลอสังหาริมทรัพย์มักจะชะงักที่ขั้นตอนการทำเอกสารสัญญา นี่คือที่มาของ **Dynamic Contract Engine** ที่ช่วยลดความผิดพลาดด้านตัวเลขของเซลล์ (Human Error) และเป็นจุดขายสำคัญของโปรเจคนี้

---

## 1. กลไกการฉีดตัวแปร (Dynamic Template Injection)

บริษัทอสังหาฯ มักมีฟอร์แมตสัญญาของแต่ละโครงการ (บริษัทสแปร์ไว้หลายไฟล์)

### 1.1 วงจรชีวิตของเอกสาร
- แอดมินสามารถอัปโหลดต้นฉบับที่เป็น Microsoft Word (`.docx`) เข้าสู่ระบบ โดยในไฟล์นั้นจะมีการพิมพ์คีย์เวิร์ดพิเศษทิ้งไว้ เช่น `{{customer_name}}`, `{{sell_price}}`
- ทันทีที่คุณหมุนดีลเข้าสู่สถานะ **"ทำสัญญา (Contract Drafting)"** ระบบหน้าบ้านจะไม่บังคับให้เซลล์ไปนั่งพิมพ์ตัวเลข 15 ล้านในไฟล์เวิร์ด โค้ดจะดึงข้อมูลตัวเลขและชื่อบุคคลจาก ฐานข้อมูล เข้าไปวิ่งชน (Parse and Replace) กับตัวแปร `{{ }}` ในไฟล์ .docx ทันที
- จากนั้นเซิร์ฟเวอร์จะสั่งแช่แข็ง (Freeze) ไฟล์นั้น โดยแปลงร่างให้หลุดออกมาเป็นนามสกุล **.PDF** ป้องกันใครก็ตามแอบกดลบ 0 ขีดฆ่าทิ้งในราคาบ้าน 

### 1.2 "In-App Preview" ไร้ดาวน์โหลดขยะ
- แน่นอนว่ามือถือของเซลล์บางรุ่นเปิดไฟล์ PDF โหลดช้า โค้ดระบบมีการฝังตัว (Embed Viewer) ด้วย HTML ทำให้แอดมินหรือเซลล์หน้าไซต์งานเลื่อนตรวจทานสัญญาใบนั้นได้สดๆ บนหน้าจอมือถือก่อนส่งเข้ากลุ่มไลน์ให้ลูกค้าพิจารณา

## 2. ระบบป้องกันการลักลอบแก้เอกสาร (Tamper-Proof Storage)

สัญญาเมื่อผลิตเป็น PDF มีมูลค่าทางกฎหมาย โลกของซอฟต์แวร์เสี่ยงต่อข้อหาที่ว่า "ถ้ามีแฮกเกอร์ฝั่งลูกค้ามาอัปโหลด PDF ทับสัญญาฉบับเก่าล่ะ?"

### 2.1 Storage Policies
- ファイルต่างๆ ที่อยู่ใน Bucket `contracts` ของ Supabase ถือเป็นข้อมูลระดับปกปิด (Confidential)
- โค้ดบังคับให้ลิงก์สูบไฟล์ (Download Link) จะอยู่ในรูปแบบ **Signed URLs** ที่มีอายุขัยสลายไปเองภายใน 15 นาที
- **Immutability (ต้านการแก้ไข):** การอัปโหลดสัญญาจะเป็นการสร้าง UUID ก้อนใหม่ของไฟล์เสมอ เราไม่อนุญาตให้มีการสั่ง "อัปโหลดทับไฟล์เดิม (Overwrite)" เด็ดขาด เพื่อป้องกันการถูกสลับเนื้อหาสัญญาในไฟล์หน้าตาและชื่อเดิม

## 3. E-Signature Workflow (เตรียมพร้อมลายเซ็นดิจิทัล)

เมื่อเทคโนโลยี NDID ถูกยอมรับกว้างขวาง สัญญาไม่ได้จำเป็นต้องใช้กระดาษเสมอไป 
- โค้ดของระบบเปิดช่อง Pipeline ทิ้งไว้รองรับ Webhook จากพาร์ทเนอร์ภายนอก (เช่น DocuSign / Adobe Sign)
- ทันทีที่ลูกค้าเซ็นชื่อด้วยนิ้วเสร็จข้ามระบบ Webhook ขากลับจะยิงเข้าโค้ดเรา และ Trigger ฟังก์ชันเปลี่ยนสเตตัสในฐานข้อมูลว่า `contract_status: 'SIGNED'` 
- เอเยนต์จะได้รับการแจ้งเตือน (Line Flex Message Push) ทันทีบนมือถือ และระบบจะทำการเก็บแฮชไฟล์ฉบับสมบูรณ์ (Timestamp Hash) ซีลถาวรลงฐานข้อมูลครับ
