# 🕵️ 09: ระบบตรวจสอบประวัติและลบรหัสวิกฤต (Audit Tracking & Visual Diff)

> **โครงสร้างหลัก:** PostgreSQL Table Partitioning, JSONB Snapshots
> **เป้าหมาย:** สร้างระบบการจดจำประวัติศาสตร์ที่ดัดแปลงแก้ตัวไม่ได้ สเกลได้ร้อยล้านแถว

การปล่อยให้พนักงานกว่าร้อยคน เข้ามาจัดการตัวเลขธุรกรรมสัญญาอสังหาริมทรัพย์ระดับหลายสิบล้านบาท ย่อมเกิด Human Error นี่ไม่ใช่แค่การเก็บ "Log ของระบบ" ธรรมดา แต่คือระบบ **Time-travel ทะยานประวัติศาสตร์ขั้นลึก**

---

## 1. Table Partitioning (ป้องกัน Audit บวมแตก)

บริษัทใหญ่ๆ มักเจอปัญหา Database ล่มสลายหลังจากใช้งานซอฟต์แวร์ไปแล้ว 2-3 ปี เพราะฐานข้อมูลตาราง Logs มีข้อมูลมหาศาลจนคำสั่ง Select ต้องทำงานหนักมาก

### 1.1 กระบวนทัศน์การหั่นชิ้นเค้กรายเดือน
ตาราง `audit_logs` ของเราไม่ได้เปิดให้โยนข้อมูลทั้งทศวรรษลงกระจุกเดียว เราฝังกลไก **Table Partitioning แยกหั่นรายเดือน** ของ PostgreSQL (อาทิ `audit_logs_2026_04`, `audit_logs_2026_05` )
- หากแอดมินต้องการค้นหาว่าใครลบสัญญาเมื่อวันศุกร์ Database ไม่ต้องไปกวาดข้อมูลของ 3 ปีที่แล้ว แต่จะเจาะจงมองแค่กระดาษ Partition ของเดือนเมษายน ทำให้ผลเสิร์ชย้อนอดีตออกผลรวดเร็วระดับ 100 milliseconds
- **Data Scrubbing**: เมื่อบริษัทยืนยันให้ทำลาย Log เกิน 2 ปีตามนโยบาย PDPA สามารถสั่ง **DROP Table Partition** ของเดือนเก่านั้นๆ ได้ในโค้ดบรรทัดเดียว เป็นการปลดปล่อยพื้นที่ฮาร์ดดิสก์แบบหมดจด ต่างจากการสั่ง DELETE Rows ที่ใช้เวลาและพื้นที่สะสม

## 2. Visual Diff Timeline & JSONB Snapshot

เมื่อของพัง ใครคือต้นตอ? ระบบ Audit ของเราตอบได้ 100% ครบทุกบรรทัดการแก้ไข!

### 2.1 บีบอัดรูปถ่ายข้อมูล (The Data Snapshots)
ในทุกๆ CRUD Operations ที่เกิดขึ้นในตารางสำคัญ ฟังก์ชันเบื้องหลังบันทึกจะปั๊มสิ่งที่เรียกว่า **Snapshot (`previous_data` & `new_data`)** ลง JSONB 
หากเซลล์คนนึงเข้าไปลบ "เครื่องซักผ้า" ออกจากช่องรายการเฟอร์นิเจอร์ และแก้ราคาขึ้นไปอีก 1 แสน ทฤษฎีนี้จะเก็บสภาพของบ้าน "ก่อน" และ "หลัง" การกระทำไว้อย่างละเอียด

### 2.2 Time-travel & UI Restoration 
ทีม Front-end จัดการตีแผ่ข้อมูลดิบผ่านหน้าต่าง Timeline บน UI:
- **ไฮไลต์ความต่าง (Diff Highlighting)**: หน้าเว็บจะเน้นสีแดง-สีเขียว เหมือนโปรแกรมสายเจาะโค้ด (GitHub) ให้ผู้จัดการรู้ทันทีว่าบรรทัดไหนเปลี่ยน ฟิลด์ไหนโดนลบ
- **ปุ่มกู้ชีวิต (1-Click Revert Button)**: เมื่อจับได้แล้วว่าพนักงาน A กดยกเลิกดีลมูลค่าสิบล้านแบบผิดพลาด ผู้บริหารสามารถกดปุ่ม "Restore Version" รันตัวแปลข้อมูล `previous_data` ถีบกลับเข้าไปสับเปลี่ยนของใหม่ใน Database ฟื้นคืนชีพดีลนั้นได้ราวกับปาฏิหาริย์ 

ระบบนี้เปรียบราวกับ "กล่องดำกู้ภัยของเครื่องบิน" ที่ถูกบังคับผสานอยู่ในเลเยอร์ความปลอดภัยพื้นฐานของตัวซอฟต์แวร์เลยทีเดียว!
