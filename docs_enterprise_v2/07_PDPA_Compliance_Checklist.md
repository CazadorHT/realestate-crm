# ⚖️ 07: ระบบคัดกรองข้อมูลและกฎหมาย (PDPA & Data Governance)

> **โครงสร้างสนับสนุน:** Soft-Deletes, Audit Partition Dropping, Dynamic Consent
> **สภาวะฉุกเฉิน:** การตอบรับกับสิทธิ์การถูกลืม (The Right to be Forgotten)

บริษัทระดับแนวหน้าที่เตรียมตัวเข้าตลาดหลักทรัพย์ (IPO) ไม่สามารถเอาซอฟต์แวร์ไร้ที่มาไปใช้ได้เด็ดขาด เพราะ พ.ร.บ. คุ้มครองข้อมูลส่วนบุคคล (PDPA) มีโทษปรับรุนแรง เอกสารฉบับนี้อธิบายถึงฟันเฟืองภายในของระบบที่ทำให้เรา "Clean & Compliant"

---

## 1. ภาวะขัดแย้งระหว่าง Audit Log กับ PDPA

ระบบได้วางโครงสร้างตาราง `audit_logs` บันทึกแบบละเอียดยิบเป็น Timeline Snapshot (อธิบายในหัวข้อ 09) แต่นั่นกลายเป็นปัญหากับกฎหมาย! หากลูกค้าร้องขอ "สิทธิ์การลืมข้อมูล" เราไม่สามารถเก็บชื่อ นามสกุล และเลขบัตรปชช. ของเขาไว้ใน Log ได้ตลอดกาล

### 1.1 กระบวนการ Data Scrubbing (การลบหมึกข้อมูลทิ้ง)
- **Soft Deletes ตามปกติ:** เมื่อแอดมินกดลบชื่อลูกค้า โค้ดจะอัปเดต `deleted_at = now()` เพื่อดันลงถังขยะ ให้ลูกค้าหายไปจากระบหน้าเว็บทันที
- **Shredding the Black Box (เมื่อลูกค้าขอให้ลบขาด):** หากมีคำร้องเป็นทางการ ระบบมีฟังก์ชันพิฆาต Database RPC นามว่า `permanently_purge_lead` คำสั่งนี้จะทะลวงเข้าไปใน `audit_logs` หาบรรทัด JSONB ที่บันทึกเกี่ยวพันกับ UUID ลูกค้ารายนี้ทั้งหมด แล้ว **"เขียนทับค่า Value ให้กลายเป็น *[REDACTED]*"** 
- ด้วยเทคนิคนี้ Timeline ประวัติยังโชว์อยู่ว่า "เซลล์ A มีการยกเลิกสัญญา" แต่จะไม่หลงเหลือชื่อหรือเบอร์โทรลูกค้าเก่าอยู่ในระบบแบบ 100% 

### 1.2 Table Partition Dropping (การระเบิดแฟ้มเก่าทิ้ง)
ทางเลือกเสริมสำหรับองค์กรที่มีนโยบายเก็บ Log แค่ 3 ปี ตามที่เอกสารเรื่อง Partitioning ระบุไว้ เราสามารถสร้าง Cron Job มารันคำสั่ง `DROP TABLE audit_logs_2023_01;` ทิ้งได้เลย ทั้งฮาร์ดดิสก์และข้อมูลลูกค้าเก่าเก็บจะถูกล้างทิ้งโดยปราศจากรอยต่อและภาระเซิร์ฟเวอร์

## 2. การควบคุม Cookie Consent สายพันธุ์ลูกผสม (Hybrid Tracking)

เนื่องจากระบบมีฟีเจอร์วิเคราะห์ Conversion สไลด์รูปทรัพย์ผ่าน GTM และออโตเมชัน:
- เราไม่เลือกใช้แค่ Banner "กดโอเคมั่วๆ" ปลายแถว
- เซิร์ฟเวอร์จะปฏิบัติต่อ Next.js Middleware อย่างเคร่งครัด หากไม่พบเซสชันการกดยอมรับแบบเลือกกลุ่ม (Marketing vs Analytics) ตัว `<script>` ฝั่ง GTM และ TikTok Pixel จะไม่ถูกโหลดขึ้นมา (No Network Requests) อย่างเด็ดขาด
- รหัส Tracking เป็น Server-to-Server (S2S) ในจุดที่ละเอียดอ่อน แทนที่จะยิงจากเครื่องลูกค้า (Client-side) ทำให้การดักขโมยข้อมูลการกดของผู้ใช้งานแทบจะเป็นไปไม่ได้ 

สรุปคือ ลูกค้าองค์กรสามารถหลับสบายโดยไม่ต้องกลัวจดหมายเตือนจากกระทรวงพาณิชย์ หรือฝ่ายกฎหมายครับ
