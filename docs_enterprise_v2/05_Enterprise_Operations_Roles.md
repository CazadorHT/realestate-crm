# 🏢 05: ปฏิบัติการระดับองค์กรและโครงสร้างทีม (Enterprise Operations & Roles)

> **โครงสร้างหลัก:** Multi-Tenant Architecture, Branch Isolation
> **เป้าหมาย:** สานต่อรูปแบบบริษัทอสังหาฯ ที่มีหลายสาขา โดยรวมสูตรการแบ่งปันข้อมูลและปิดกั้นข้อมูลขั้นเด็ดขาด

เมื่อถึงเวลาที่ CRM ของเราไม่ได้ให้บริการแค่บริษัทเล็กๆ แต่เป็นโครงข่ายแฟรนไชส์ที่มีสาขากระจายทั่วประเทศ 100 สาขา การจัดการ "ผู้อยู่เบื้องหลัง (Operations)" จึงเป็นเรื่องของโครงสร้าง Tenant อย่างหลีกเลี่ยงไม่ได้

---

## 1. Multi-Tenant Branch Isolation (สถาปัตยกรรม "ขังเดี่ยว" ของแต่ละสาขา)

โครงสร้างฐานข้อมูลออกแบบมาให้ **Tenant-first** ทุกบริษัท (หรือสาขา) จะมี `tenant_id` เป็นกุญแจประจำตัว และผู้ใช้ทุกคนรวมถึงข้อมูลทุกอย่าง (บ้าน, ลูกค้า, คอมมิชชัน) จะต้องถูกประทับตรากุญแจนี้

### 1.1 กระบวนทัศน์กำแพงใส (Glass Wallet Approach)
- **สิทธิ์ขาดแบบเด็ดขาด:** พนักงานที่อยู่สังกัด `สาขาสุขุมวิท` จะค้นพบและเข้าถึงลูกค้าได้เฉพาะที่ตีตราว่าสุขุมวิท ต่อให้ตั้งใจพิมพ์ URL ผิดข้ามไปดู Data ของ `สาขารัชดา` หน้าเว็บก็จะตีเบลอ (404 Not Found) ทันทีเพราะมี RLS ปกป้องตั้งแต่ระดับ Data layer
- **Global Inventory (ระบบ Co-Brokerage):** หากบริษัทแม่ (Headquarter) กำหนดนโยบาย "แชร์สต็อกบ้าน" ระบบรองรับการตั้งค่าตารางทรัพย์บางเส้นให้เป็น Public Read Across Branches ได้ เพื่อให้สาขาสุขุมวิท เอาคอนโดของรัชดาไปขายเพื่อแบ่งเปอร์เซ็นต์แบบ Co-Agent โดยที่สาขาสุขุมวิทไม่มีสิทธิ์ไปกดลบหรือกดแก้ไขข้อมูลตัวบ้านได้

## 2. ทะเบียนตำแหน่งสายงาน (Enterprise Role Hierarchy)

ไม่ใช่แค่ "แอดมิน" กับ "ยูสเซอร์" แบบซอฟต์แวร์ธรรมดา โครงสร้าง Role System ถูกออกแบบมาสำหรับองค์กรหลายชั้น:

### 2.1 The Executive (ผู้บริหารระดับสูง)
- เผ่าพันธุ์ที่อยู่เหนือ Tenant! ระบบอนุญาตให้ผู้บริหารสามารถใช้ปุ่ม **"Branch Switcher"** เลือก Dropdown สลับดูภาพรวมสาขาทุกตารางทั่วประเทศได้จากหน้าจอเดียว 
- สามารถดู Report สรุปผลประกอบการแบบ Global Consolidation (นำรายได้ทุกสาขามามัดรวมกันเพื่อเสนอเข้าบอร์ดบริหาร)

### 2.2 Branch Manager (ผู้จัดการสาขา)
- รับบทเป็น "พระเจ้าของสาขานั้นๆ" 
- เปลี่ยน Logo และ Color Theme แยกตามสาขาได้ (Live Customization)
- เป็นคนที่มีอำนาจในการกดปุ่ม "กู้คืน (Restore)" สถานะบ้านและสัญญาจาก Timeline ได้ 

### 2.3 Agent (พนักงานขาย)
- เห็นเฉพาะทรัพย์ที่ตนเองดูแล และเห็นดีลที่ชื่อตัวเองถูกสลักไว้ว่าเป็นผู้รับผิดชอบ (Assigned User)
- โดนจำกัดโควต้าการใช้ AI ประเมินราคาผ่านระบบ จำกัด Rate Limit ป้องกันการผลาญ Token ของบริษัท

การวางโครงสร้างลอยตัวแบบ Multi-tenant เช่นนี้ ทำให้ซอฟต์แวร์กลายร่างเป็น "SaaS Factory" ที่คุณสามารถสร้างแพ็กเกจขายให้ตัวแทนอสังหาริมทรัพย์เจ้าอื่นเข้ามาเปิดเต็นท์เช่าระบบคุณได้อย่างปลอดภัยครับ!
